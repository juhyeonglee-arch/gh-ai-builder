# 개발 노트

빌더 구조, 그래프 JSON 형식, 예제 설계, 검증 도구, 겪었던 오류와 남은 일을 정리한 문서예요.

## 3. 빌더 (`src/GH_AI_builder.py`, v0.9)

- **실행:** Rhino 명령창에서 `RunPythonScript` → 이 파일을 선택하면 Eto 창이 떠요.
- **버튼**
  - **[새로 만들기]:** JSON(첫 글자 `{`)이면 API 없이 바로 지어요. v0.9부터는 캔버스에 있던 예전 GH AI 정의를 **지우고 같은 자리에** 지어요. 체크박스로 끌 수 있어요.
  - **[지금 정의 고치기]:** 현재 정의를 지우고 다시 지어요. 사용자가 바꾼 슬라이더 값은 유지해요.
  - **[결과 Bake]**
    - 아무것도 선택하지 않으면 캔버스의 GH AI 정의를 전부 Bake해요.
    - 같은 **제목**의 예전 Bake 결과는 지우고 바꿔요. 객체 UserString `GH_AI = "title:<제목>"`으로 구별하고, 예전 판이 쓰던 패널 GUID 표도 지워요.
    - 컴포넌트를 선택하고 누르면 선택한 것만 Bake해요(이때는 지우지 않고 더해요).
  - **[지금 정의 JSON 복사]:** 슬라이더 값까지 담은 현재 정의를 클립보드에 복사해요.
  - **[컴포넌트 목록 저장]:** 바탕화면에 `GH_컴포넌트목록.txt`를 만들어요. 설치된 모든 컴포넌트의 입력·출력 이름이 들어 있어요.
- **정의 저장:** 캔버스의 패널 `GH_AI_DATA (지우지 마세요)`에 그래프와 id→GUID 표를 저장해요. 그래서 .gh를 다시 열어도 Bake·고치기가 이어져요.
- **미리보기:** 중간 단계는 숨기고 Bake 대상과 `preview:true` 노드만 보여요. 블록 원형도 숨겨요(원점에 있으므로).
- **재료 → 레이어·렌더 재질**
  - 재료 7가지: `steel 강철`, `concrete 콘크리트`, `glass 유리(반투명)`, `aluminum 알루미늄`, `spandrel 스팬드럴`, `wood 목재`, `stone 석재`
  - 레이어 이름: `GH_AI::<제목>::<재료>::<부재 이름>`
- **블록:** 원점의 원형 부재들로 블록 정의 1개를 만들고, `at` 노드의 평면마다 인스턴스를 놓아요. 변환은 `PlaneToPlane(WorldXY, plane)`이고, 점이 오면 WorldXY 평면으로 바꿔요.

### 그래프 JSON 형식 (줄임 표기)

```json
{
  "title": "...", "summary": "...", "notes": "...",
  "groups": [{"id": "g1", "label": "1. 입력", "note": "..."}],
  "nodes": [
    {"id": "sN", "component": "Params/Input/Number Slider", "group": "g1", "nickname": "층수", "slider": [8, 80, 50], "int": true},
    {"id": "p2", "component": "Params/Input/Panel", "text": "2"},
    {"id": "tog", "component": "Params/Input/Boolean Toggle", "toggle": false},
    {"id": "slab", "component": "Surface/Freeform/Extrude", "nickname": "슬래브", "bake": true, "material": "concrete"},
    {"id": "pv", "component": "Transform/Euclidean/Orient", "preview": true}
  ],
  "wires": [["sN", "", "htot", "A"], ["fpoly", "Polygon", "mg", "Data 1", "graft"]],
  "blocks": [{"name": "커튼월 유닛", "parts": ["mL", "mR", "gls"], "at": "ppl"}]
}
```

- `component`는 `"카테고리/하위카테고리/이름"` 형식이고, 실제 이름은 `tests/real_catalog_rhino8.txt`에 있어요(사용자 PC에서 뽑은 855개).
- 선은 `[보내는 노드, 출력 이름, 받는 노드, 입력 이름, (graft|flatten)]` 순서예요. 이름 대신 별명이나 순번도 받지만, 정식 이름을 쓰세요.
- `bake:true`가 하나도 없으면 선이 더 나가지 않는 마지막 컴포넌트를 Bake해요. 블록이 있으면 표시한 노드만 Bake해요.

### 08 타워 설계 요약

- **평면과 비틀림:** 정사각형 평면, 층마다 `회전 = 높이 × (총 비틀림 ÷ 건물 높이)`. 기본값은 50층 × 4m에 60°예요.
- **켜 나누기:** 바깥 유리 선(한 변 36m) → 150mm 안쪽에 슬래브 끝 → **1,800mm 안쪽에 다이아그리드 중심선**. 간섭 검사 결과 구조가 유리에서 최소 350mm 떨어져요.
- **구조**
  - 4층마다 링을 두고, 링마다 반 칸씩 엇갈린 절점을 찍어요.
  - Flip Matrix와 Shift List(−k)로 두 방향 나선을 만들어요.
  - 대각재는 H형강(700×450)으로, 춤이 바깥을 향해요.
  - 링 보는 춤이 수직이고 슬래브 밑에 매달려요.
  - 바닥 보는 켜기 스위치로 따로 켜요.
  - 슬래브는 층 높이에서 아래로 두께만큼 놓여요.
- **블록**
  - **주강 노드:** 축이 바깥을 향하는 원반(드럼 + 캡), 1,008개.
  - **엔드 플레이트 + 볼트 10개:** 대각재 양 끝마다, 3,869개.
  - **커튼월 유닛:** 멀리언, 트랜섬 3개, 스팬드럴, 복층 유리, 외부 캡. 51층 × 96장 = 4,896개.
  - **커튼월 코너 기둥:** 204개.
- **알려진 점**
  - 노드 윗부분이 슬래브를 관통해요. 실제 다이아그리드도 그렇지만, 보기 싫으면 노드 지름을 줄이세요.
  - 비틀림을 90°보다 크게 하면 노드가 유리에 닿을 수 있어요. 이때는 '유리 → 다이아그리드 중심 거리'를 늘리세요.
  - 층마다 패널이 돌아가서 멀리언이 층 사이에서 엇갈려요. 의도한 계단형 외피예요(Cayan Tower 방식).

## 5. 검증 도구 (보내기 전 필수) — `tests/`

Rhino가 없는 환경에서도 JSON을 미리 계산하고 그려 볼 수 있게 만든 도구예요.

1. **이름 검사:** `python3 tests/check_examples_real.py` → 예시 JSON 전부의 컴포넌트·입력·출력 이름을 실제 목록과 맞춰 봐요. 오류가 0개여야 해요.
2. **그래스호퍼 흉내 검사기:** `python3 tests/ghsim.py <json> [out.png]`
   - 데이터 트리 규칙을 흉내 내요: 가지 짝짓기, 가장 긴 목록, Graft/Flatten, 리스트 출력 경로.
   - 사용하는 컴포넌트 약 55개를 점·벡터·평면·꺾은선·면으로 계산해요.
   - **입력 기본값은 실제 그래스호퍼와 같게** 맞췄어요. 특히 Evaluate Length의 Normalized 기본값은 True예요.
   - 출력: 오류·경고, Bake 결과(블록 배치 포함). PNG는 간이 그림이에요.
   - 새 컴포넌트를 쓰려면 `@comp(...)`로 먼저 추가하세요. 없으면 "검사기에 없는 컴포넌트" 오류가 나요.
3. **간섭 검사:** `tests/tools/clash.py`. 구조 부재의 꼭짓점과 그 층 유리 선 사이의 최소 거리를 재요.
4. **실제 렌더:** `tests/render/`
   - `export_tris.py`가 재료별 삼각형을 내보내고, `render.js`가 three.js로 headless Chromium에서 PNG를 찍어요.
   - three.js는 `npm install three@0.170.0`으로 받고, 환경변수 `THREE_JS`로 `three.module.js` 경로를 넘겨요.
   - 예시 실행 스크립트: `tests/tools/views.py`.
   - 큰 모델(삼각형 180만 개)은 내보내기에 약 25초, 한 장 찍는 데 약 5초 걸려요.
5. 그림(`renders/`)을 직접 보고 형상이 맞는지 확인한 뒤에 사용자에게 보내요.

## 6. 꼭 기억할 교훈 (실제로 겪은 오류)

1. **Evaluate Length는 Normalized 기본값이 True예요.** mm로 잴 때는 반드시 False 토글을 연결하세요.
   - 07은 이것 때문에 대각재와 링 보 전체가 오류(빨강)가 나서 구조가 빠졌어요.
   - 02 벽돌 벽은 원호 곡선이 범위 밖까지 계산돼 C자로 말렸어요.
2. **Rectangle의 X/Y Size는 구간(Domain)이에요.** 숫자를 넣으면 0~값이 되어 모서리에 붙어요. 가운데에 놓으려면 −½~+½ 구간을 만드세요.
3. **실제 이름 예시**
   - Vector 2Pt 입력은 `Point A` / `Point B`예요(Base/Tip Point가 아님).
   - Scale은 `Transform/Affine/Scale`이에요.
   - Center Box의 X/Y/Z를 절반 크기로 가정했는데, 아직 확인하지 못했어요.
4. **[새로 만들기]가 예전 정의를 지우지 않으면** 캔버스에 2개, 3개가 쌓였어요(v0.9에서 고침).
5. **블록 Bake:** 예전 판은 마지막 정의만 Bake하거나 두 번 Bake했어요. v0.7부터 모든 정의를 Bake하고, v0.9부터 제목으로 바꿔치기해요. v0.6 이전에 Bake한 객체에는 표가 없어서 손으로 지워야 해요.
6. 그래스호퍼 미리보기(점 x 표시)가 사용자를 헷갈리게 했어요 → 중간 단계를 숨겼어요(v0.8).
7. **보내기 전에 검사기·렌더로 확인하기.** 이 단계가 없던 07에서 사용자가 "뭐야 이상하잖아", "진짜 왜 그러냐"라고 했어요.
